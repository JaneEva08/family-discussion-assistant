# Помощник семейного обсуждения

Telegram-помощник для общей учебной группы: сохраняет реплики после явного
начала записи, находит контекст, отвечает на «Что думаешь?» и подводит итог.
Продолжение проекта «Тема понятна»: индивидуальные занятия остаются в веб-приложении,
этот этап добавляет обсуждение с родителем и двумя ученицами.

## Три Haystack Pipeline

- Индексация: MessageDocument → IndexMessages → Pinecone.
- Поиск: RetrieveDiscussion → Discuss; семантические результаты дополнены
  последними 16 репликами, чтобы сохранять уточнения и отрицания.
- Суммаризация: ReadSession → Summarize; рассматриваются все сообщения
  текущего обсуждения, при необходимости группами с объединением итогов.

Чаты разделены namespace, обсуждения — фильтром session/chat. В метаданных
сохраняются автор, ID автора, ID сообщения, время, исходный текст и сессия.
Ответы модели и команды не индексируются как реплики участников.
SQLite сохраняет хронологию, состояние записи и polling offset после перезапуска.

## Запуск

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# Заполнить локальные ключи.
.venv/Scripts/python.exe bot.py
```

Используются согласованные OpenAI-compatible base URL/model и Pinecone.
Эмбеддинги multilingual-e5-large, 1024/cosine из предыдущих этапов.
Исходный tutorial Extractive QA скачан в корень как образец структуры;
источник, лицензия и отличия реализации описаны в TUTORIAL-SOURCE.md.
Notebook не запускается автоматически.

## Команды и сценарий

`/listen` — начать обсуждение; повторная команда не очищает активную сессию.
`/stop` — остановить запись, затем выдать итог.
`/summary` — получить итог текущего/последнего обсуждения.
`/ask вопрос`, `@имя_бота вопрос`, `Что думаешь?` — ответ по контексту.
`/status` — состояние и количество локальных/проиндексированных сообщений.
`/help` — справка. После остановки обычные сообщения не записываются.
Новый `/listen` после `/stop` создаёт отдельную сессию, старые данные сохраняются.

Для группы включать/останавливать запись может её администратор.
Чтобы бот видел обычные сообщения, он должен быть администратором группы
или работать с отключённым privacy mode: https://core.telegram.org/bots/faq#what-messages-will-my-bot-get.
Для теста выбирайте отдельную учебную группу; запись и передача данных
сервисам объявляются командой `/listen`. В личном чате можно проверить
однопользовательский сценарий, но он не подтверждает работу нескольких участников.

## Проверки

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe probe.py
```

10 тестов: запись только после старта, права администратора, отсутствие
самоцитирования, повторный старт, разделение чатов/сессий, дубли, сохранение
автора/данных при новом подключении и предел сообщений.
`probe.py` использует реальные сервисы и только авторское тестовое обсуждение.
Проверены уточнение расписания, поиск, итог и изоляция другого чата.
Результаты — results/service-checks.json. Telegram-сценарий проверяется отдельно.

## Ограничения

До 60 текстовых сообщений по 2000 символов на обсуждение. Редактирования,
удаления, вложения и форумные темы отдельно не обрабатываются; тема Telegram
внутри одной группы не является отдельным пространством памяти.
При ошибке записи Pinecone сообщение остаётся локально, `/status` показывает
разницу; автоматической фоновой повторной индексации нет. Суммаризация читает
всю локальную сессию, поиск использует Pinecone и последние 16 реплик.
Нет автоматической очистки облачной истории или постоянного хостинга.
Ключи, логи и реальная переписка в Git не включаются.

Исправление группового доступа: ALLOWED_USER_IDS ограничивает личный чат и первоначальное подключение группы. После разрешённого старта учитываются реплики всех участников группы. Два регрессионных теста проверяют этот сценарий и сохранение ограничений для личного чата/новой группы.
